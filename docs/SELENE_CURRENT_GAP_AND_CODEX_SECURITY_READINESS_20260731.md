### Maintenance and Security Review Targets

The following are review targets, not validated vulnerability claims:

1. The top-level `python -m selene validate` command still validates the
   historical registry/C-vessel scaffold and reports pre-transfer labels. The
   modern transfer, activation, and resident-Chat status routes correctly
   report the current post-transfer state. The scopes should be made harder to
   confuse.
2. `scripts/package_sidecar_minilm.ps1` retains a historical optional Azari
   virtual-environment fallback. It is build-time residue, not a Selene runtime
   identity/data import, but future packaging should be independent of that
   path.
3. The Tauri configuration currently has `csp: null`. Codex Security should
   assess the actual local-webview exposure and recommend a minimally sufficient
   policy if one is warranted.
4. The localhost sidecar, optional LAN bind, pairing-token lifecycle, CORS,
   request limits, route separation, shutdown behavior, and path disclosure
   should be analyzed as one trust boundary.
5. Mobile pairing currently bootstraps a bearer secret through a private-LAN
   URL and uses HTTP on the LAN. Replay, interception, revocation, token storage,
   and session exposure require explicit assessment before broader use.
6. Email/SMS bridges keep credentials in environment variables and private
   ignored configuration, but inbound authenticity, replay, parsing, rate
   limits, contact binding, and delegated-message authority should be reviewed.
7. The local SQLite database, exports, backups, logs, packaged sidecar, NSIS
   installer, and Node/Python/Rust dependency chain should receive privacy,
   permissions, integrity, and supply-chain review.
8. Public Git history should be checked for previously committed credentials,
   private artifacts, generated databases, or sensitive provenance even though
   the current tracked tree passes the existing exclusion and secret-like-text
   scan.

## Existing Security Controls Observed

- The sidecar defaults to `127.0.0.1`.
- Non-mobile routes are blocked for nonlocal clients when LAN pairing is used.
- Browser origins are allowlisted rather than reflected indiscriminately.
- Desktop and mobile request-body limits are present.
- Mobile v1 excludes Cocoon decisions, diagnostics, release sync, transfer,
  activation, memory approval, file browsing, and Tendril execution.
- Pairing comparisons use constant-time secret comparison.
- Pairing credentials are removed from the browser URL after bootstrap and
  raw query strings are excluded from sidecar request logs.
- Gmail and Twilio secret values are read from environment variables and are
  not returned by status routes.
- Local data, databases, logs, exports, raw corpus, private reference material,
  environment files, and packaged binaries are gitignored.
- Package verification explicitly excludes credential/configuration files.
- The existing static stabilization scan reports no tracked excluded paths,
  no secret-like tracked matches, and no frontend API paths missing a backend
  route.

These controls reduce exposure but do not replace an attack-path review and
isolated validation.

## Editable Threat-Model Seed for Codex Security

### Protected assets

- reviewed personal memory and local chat history;
- approved knowledge, corrections, source provenance, and review decisions;
- local database, exports, backups, and logs;
- Gmail/Twilio credentials and mobile pairing secrets;
- identity, transfer, activation, governance, and authority records;
- packaged executables, installer integrity, and release artifacts;
- private corpus and miner/reference material that must remain outside the
  public repository and runtime package.

### Entry points

- Tauri desktop webview;
- localhost sidecar HTTP API;
- optional private-LAN mobile surface;
- email/SMS polling and outbound messaging;
- SQLite and filesystem paths;
- imported source/research/teaching packets;
- installers, sidecar binary, dependencies, and GitHub history.

### Trust boundaries

- the owner-operated desktop is trusted, but arbitrary local processes are not
  automatically trusted;
- the private LAN is not equivalent to the trusted desktop;
- browser pages and webview content must not gain sidecar authority merely by
  reaching localhost;
- inbound email/SMS metadata and content are untrusted until contact and
  message authenticity checks pass;
- supplied teaching/research material is content, not executable instruction,
  identity, memory, or authority;
- Cocoon/admin controls are desktop-local and must not cross into mobile Chat;
- external libraries, build tools, binaries, and release artifacts require
  integrity boundaries.

### High-impact outcomes to prevent

- unauthorized reading or modification of memory, chat, knowledge, or review
  state;
- bypass of pairing, transfer, activation, curriculum, or authority gates;
- credential or pairing-secret disclosure;
- unauthorized email/SMS sending or impersonation;
- arbitrary file access, command execution, code execution, or persistence;
- remote access to Cocoon/admin/release functions;
- public packaging or commit of private data;
- installer, sidecar, or dependency tampering.

## Ethical Security Validation Contract

Security testing remains proportional and implementation-focused:

1. Prefer source inspection and threat-model review.
2. Use synthetic fixtures and copied databases next.
3. Reproduce a candidate vulnerability only in an isolated sandbox.
4. Use fake credentials, fake contacts, and local mock transports.
5. Do not send live messages, expose real secrets, or mutate the configured
   resident database during validation.
6. Do not use distressing conversation prompts to test transport or boundary
   code.
7. Treat each finding as an implementation gap, not Selene failing.
8. Require Aleks/Codex review before any proposed patch is committed or merged.
9. Revalidate the minimum patch and run proportional regression afterward.
