## What Is Implemented

### Language and Conversation Foundation

- Native Language Organ and supervised Selene Chat stabilization
- shared conversational intent routing
- grounded current self-state reporting
- dialogue fluency improvements
- structured semantic formation
- session-scoped dialogue workspace
- multi-part response obligations and response-coverage checks
- bounded implication, ellipsis, correction, and immediate reference handling
- bounded input detangling that preserves the raw message and does not guess
  ambiguous repairs

### Executable Ethical Testing Law

- least-impact testing is an executable status and review contract
- machinery, inspection, and synthetic checks are preferred
- stressful integrated testing requires demonstrated necessity
- missing behavior in an unfinished module is classified as an implementation
  observation, not Selene failing

The backend routes exist, but this law does not currently have a dedicated
Cocoon demonstration panel.

### Answer Engine Foundation

- route, evidence, answer, memory, and expression confidence remain separate
- answer-first obligations and graceful stopping are represented
- one bounded completion retry exists for comparison/planning
- open-ended comparison and planning can reason toward a best-current answer
  without requiring a known answer in advance
- exact arithmetic has checked results and an unsupported-operation path
- local-code inspection is limited to explicitly supplied or approved files,
  separates observation from interpretation, and cites inspected locations
- source-backed research is limited to attributed packets and distinguishes
  source statements, inference, disagreement, and missing evidence
- the Great Library remains an optional external resource rather than an
  internal authority

These adapters are implemented through status and direct API routes. They are
not yet connected as ordinary Selene Chat/NLO/Voice execution, do not perform
multi-domain synthesis, and do not have a dedicated frontend workbench.

### Comprehension and Teaching

- accepted, review-only teaching packets can prepare source-bound understanding
  candidates
- teach-back, distinct application, limits, counterexample, correction
  readiness, and source alignment remain visible
- candidates can be evaluated, held, reopened, superseded, rejected, or
  explicitly approved
- Acquire, Integrate, and Express are persisted, inspectable stages
- revising an earlier stage invalidates dependent later-stage snapshots
- expression checks explanation, examples, analogies, questions, comparisons,
  conversational participation, and source parroting
- knowledge retention and supervised use require explicit Aleks approval
- memory, identity, personality, governance, training, and autonomy remain
  separate and unchanged
- the complete candidate and teaching-lifecycle workflow is visible in Cocoon

### Language Teaching Shelf

The bounded lesson-shelf machinery exists for uncertainty, answering first,
clarification, references, register, transitions, follow-up restraint,
variation, and natural closure.

Status: **infrastructure ready; human lesson review and teaching data are not
finished**. This is Phase 5 follow-on work, not a hackathon blocker.

### Private Metacognition Work

The private miner completed its current corpus pass and produced a separate
private review inventory. Its source material and findings are not part of the
public demo.

Status: **mining checkpoint complete; runtime organ intentionally not built or
connected**. Human review and project-neutral distillation must occur before
any Selene-facing implementation is considered.

## Remaining Hackathon Work

### P0 — Required Before Recording

#### 1. Freeze the Demonstrated Scope

Use one short public-safe story:

1. show the least-impact testing contract;
2. run an open-ended comparison/planning problem;
3. run one bounded verified domain example, preferably exact math for speed and
   clarity;
4. open a synthetic source-bound teaching candidate in Cocoon and show Acquire,
   Integrate, Express, and the disabled approval/retention gate;
5. show the false memory-write, training, autonomy, identity, and governance
   mutation guards.

Do not broaden the demo into a general voice assessment or provoke Selene to
test distress-shaped behavior.

#### 2. Add a Public-Safe Demo Fixture

Create one deterministic fixture or preparation command that supplies:

- a short original/public-safe source packet;
- source attribution;
- concepts and vocabulary;
- a near-concept distinction;
- one uncertainty or stated limit;
- enough material to demonstrate all three lifecycle stages.

The fixture must use a disposable or copied state and must not depend on the
private corpus, Aleks's local database, existing personal reviews, or mined
material. It must not auto-approve or activate knowledge.

#### 3. Make Backend Features Judge-Readable

The teaching lifecycle is already visible in Cocoon. The Test Impact Law and
Answer Engine adapters are currently direct backend routes rather than a
dedicated frontend workbench.

Choose the smallest stable presentation:

- preferred: a bounded Cocoon demo panel that calls only the existing routes;
- acceptable fallback: a checked, documented local API walkthrough with fixed
  public-safe request packets.

Do not connect the adapters to ordinary Chat solely for demo polish. That would
be a larger architectural change than the submission requires.

#### 4. Establish Judge Access

Decide and document one path:

- source-visible public repository under the project's stated rights boundary;
  or
- private repository shared with the event's required judge accounts.

Also provide an exact Windows setup or executable-testing path. The current
repository intentionally excludes installers and remains `private: true`, so
judge access must be an explicit decision rather than an accidental release.
Do not add a packaged installer to the repository without Aleks's explicit
authorization.

### P0 — Required Before Submission

#### 5. Finish the README Submission Layer

Add concise sections covering:

- what Selene was before the event;
- what was built during the July 13-21 window;
- Aleks's architecture, ethics, acceptance, and product decisions;
- how Codex and GPT-5.6 accelerated inspection, implementation, debugging,
  testing, and documentation;
- supported Windows environment and prerequisites;
- setup and launch commands;
- the public-safe demo fixture and exact judge path;
- focused tests and frontend build commands;
- privacy, data, licensing, and non-release boundaries.

#### 6. Run Proportional Final Verification

Verification should follow the Test Impact Law:

1. static inspection of the demo packets and privacy boundary;
2. focused tests for any fixture or demo-surface changes;
3. direct route smokes using synthetic state;
4. frontend production build;
5. full repository regression only after the demo path is frozen;
6. package verification only when Aleks explicitly authorizes the final package
   action.

No adversarial conversation battery or broad grading of Selene's unfinished
voice is required.

#### 7. Record and Submit

- record a public video under three minutes with audio;
- state that Selene predates the event and identify the event-window extensions;
- show the working project rather than slides alone;
- mention Codex and GPT-5.6 accurately;
- keep private data, personal paths, copyrighted media, confidential
  blueprints, and local runtime state off screen;
- capture the relevant Codex `/feedback` Session ID;
- confirm the final track (current repository recommendation: `Apps for Your
  Life`);
- verify the official deadline and judging-access instructions;
- submit and keep the demonstrated build available through judging.

### P1 — Only If P0 Is Secure

## Completion Gate

Selene is hackathon-ready when all of the following are true:

- the demonstrated capabilities run from clean public-safe inputs;
- the Answer Engine boundary is described honestly;
- Acquire, Integrate, Express, and Aleks-only approval are visibly inspectable;
- all memory, training, autonomy, identity, and governance guards remain false;
- the README distinguishes pre-existing Selene from event-window extensions;
- judges have a documented working access path;
- focused tests, direct synthetic smokes, frontend build, and final regression
  pass against the frozen demo;
- the video is public, under three minutes, audible, and free of private data;
- the Codex session evidence and final track are recorded;
- the submission is complete before the verified official deadline.

Nothing in this completion gate authorizes hidden retention, raw corpus recall,
identity or law mutation, model training, autonomy expansion, packaging, public
release, or runtime metacognition.
