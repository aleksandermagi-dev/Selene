## Correction Contract

Each correction descendant records:

- parent and root concept identifiers;
- a visible reason for review;
- inherited and revision source references;
- typed source roles and the instructional-why receipt;
- unchanged original-parent preservation;
- source-review and full-lifecycle requirements; and
- an explicit no-automatic-truth boundary.

The parent becomes historical and unavailable to ordinary Chat as soon as the
descendant is opened. Repeating the same reopen returns the existing
descendant with `duplicate_open_descendant_stopped`; it creates no duplicate.
An unresolved descendant cannot reopen itself, and a superseded historical
node cannot start a competing branch. Both paths return typed terminal
receipts rather than recurse.

Teaching lifecycles inherit parent/root lifecycle identifiers. When the
descendant is approved, only its direct parent is superseded, preserving each
earlier direct link in a longer correction chain. The approved descendant is
marked as the sole active winner; all ordinary retrieval continues to require
the existing approved state, review status, and Chat-use permission.
