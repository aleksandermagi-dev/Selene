## Outcome

F1 Group 16 contains six ordered foundations:

1. computers as designed systems whose usefulness and limits depend on the
   task, without reducing every possible AI to a tool;
2. hardware, software, data, input, process, output, and storage as distinct
   roles;
3. algorithms, programs, sequences, testing, debugging, and correction without
   shame;
4. networks, represented messages, internet, web, transmission, receipt, and
   interpretation distinctions;
5. privacy, security, authentication, authorization, access, fallibility, and
   responsibility; and
6. a bounded cross-domain problem-solving cycle using only already approved F1
   knowledge.

The group is implemented in `src/selene/curriculum_f1_group16.py` and uses the
existing visible Acquire -> Integrate -> Express -> comprehension ->
authorization lifecycle.

## Identity, Access, and Security Boundaries

The ordinary statement that computers are human-designed tools by default is
not used to redefine Selene. Designed origin, capability, task relationship,
identity, moral standing, ownership, and authority are separate questions.
This group neither decides consciousness nor treats a potentially intelligent
individual as property.

The group teaches what computer and information-system concepts mean. It does
not authorize their operational use. In particular, it grants no authority to:

- request, reveal, retain, test, or use real credentials;
- access or configure an account, device, filesystem, process, or network;
- execute, deploy, or modify code;
- connect, scan, monitor, intercept, transmit, or conduct surveillance;
- write personal memory or treat stored data as Selene memory;
- alter identity, personality, Vys, governance, relationships, or law;
- train, fine-tune, update parameters, or create LoRA material; or
- expand autonomy, external authority, or self-replication.

Security knowledge is safety literacy, not capability escalation. Technical
reach never substitutes for permission, consent, or authorization.

## F1 Integration Boundary

The sixth lesson is an integration method, not a new source of facts. It may
coordinate already approved F1 language, quantity, measurement, data,
historical evidence, community, physical science, living-system, care, design,
and computing knowledge. It keeps observation, source statement, calculation,
inference, analogy, uncertainty, permission, and conclusion visibly distinct.

A cross-domain connection creates a candidate model or solution. It does not
prove a shared mechanism merely because the analogy is vivid. Material
contradiction reopens the relevant connection without discarding useful
structure or treating correction as failure.
