# Selene Post-Stabilization Gap Closure Plan

Date: 2026-07-25

Status: Step 1 implemented and focused verification passed; integrated
Phase 11F stabilization remains

Step 1 checkpoint summary (2026-07-26):

- resident post-transfer runtime truth is exposed without migrating the
  compatibility database state;
- supported semantic packets now reach NLO from Answer Engine, approved
  knowledge, reviewed memory, self-state, and bounded completion;
- Answer Engine routes obligations independently and can coordinate up to four
  connected specialized obligations;
- local-code inspection remains an explicit separate bounded route;
- Metacognition can request one owner-bounded completion or new-evidence
  recheck without writing answer content;
- focused static and synthetic checks passed, including 174 cross-organ tests
  and a production UI build;
- no live conversation, stressful probe, retention change, provider call,
  training, autonomy expansion, or reinstall was used.

## Decision

Ordered academic teaching pauses after Phase 10 stabilization.

Selene's conversation spine, provider-free text path, comprehension lifecycle,
reasoning core, Answer Engine foundations, Metacognition Organ v1, reviewed
memory access, contextual continuity, and safety laws already exist. The next
work should not rebuild them. It should close the remaining architectural
seams that affect how future knowledge will be routed, expressed, checked, and
used.

The new order is:

```text
Phase 11 — pre-teaching architecture closure
  -> Phase 12 — ordered teaching expansion
  -> Phase 13 — post-teaching ordinary-use assessment
  -> later perception, audible speech, Dream maturation, and Tendril work
```

## What Must Be Closed Before Teaching

### Phase 11A — Capability truth and post-transfer runtime audit

Purpose: make code, UI, status values, and public documentation describe the
same present system before changing behavior.

Work:

- regenerate the plain-language capability inventory from current source;
- classify each capability as connected, bounded direct route, Cocoon,
  preview, design, or deliberately blocked;
- audit legacy `supervised` and pre-transfer wording against the current
  approved transfer state;
- distinguish resident conversation, activation, reviewed memory retrieval,
  memory proposals, durable retention, delegated messaging, and consequential
  autonomy;
- identify naming-only residue separately from real behavioral limitations;
- remove stale verification counts and obsolete bundle-warning claims;
- preserve every existing law while making post-transfer state legible.

Completion gate:

- no current capability is overstated or hidden by stale terminology;
- an approval boundary is never mistaken for a missing organ;
- approved memory use is not mislabeled as raw runtime recall;
- no authority changes during the audit.

### Phase 11B — Semantic generation and routing maturation

Purpose: let NLO construct more of the visible answer from supported meaning
instead of inheriting nearly finished prose.

Work:

- inventory the remaining prose-first seams in approved knowledge, memory
  reconstruction, self-state, ordinary answer substance, and helper replies;
- migrate high-use sources toward propositions, entities, relations, scope,
  certainty, provenance, and discourse roles;
- make structured meaning the primary routing input while retaining explicit
  phrase-pattern fallback for bounded graceful fall;
- expand grammar and clause composition without treating vocabulary exposure
  as understanding;
- improve multi-paragraph reference tracking, thesis preservation,
  transitions, rhetorical emphasis, and varied grounded endings;
- carry affect and contextual modulation as optional structured guidance;
- preserve exact math, citations, quotations, route keys, and safety-critical
  wording under exactness locks.

Completion gate:

- the same supported meaning can produce several materially different,
  context-fitting realizations;
- claim, certainty, scope, source, and memory status remain invariant;
- unusual wording can route by meaning when the evidence is sufficient;
- missing content remains missing rather than becoming fluent invention;
- provider-free deterministic behavior becomes less script-audible without
  becoming random.

### Phase 11C — Answer Engine coordination

Purpose: supply complete supported content for complicated and cross-domain
questions before NLO expresses it.

Work:

- route each answer obligation to its appropriate supported source or domain
  adapter instead of selecting only one primary domain for the whole message;
- coordinate approved knowledge, intelligenceOS reasoning, verified math,
  attributed research, and ordinary comparison/planning in one answer plan;
- preserve source statement, inference, hypothesis, conclusion, disagreement,
  and missing-evidence distinctions across combined results;
- allow one bounded completion request to the responsible organ when a
  supported obligation is missing;
- decide explicitly whether local-code inspection joins ordinary Chat;
- if connected, limit code inspection to files Aleks supplies or approves,
  with no autonomous scan, execution, write, or authority expansion;
- keep external source acquisition separate and explicitly enabled; never
  invent citations or silently make the Great Library an internal authority.

Completion gate:

- a supported multi-part question can receive content from more than one
  domain without losing confidence or provenance separation;
- unsupported parts fall gracefully and remain visible;
- NLO cannot manufacture domain content to satisfy coverage;
- local-code behavior remains bounded whether it stays separate or joins Chat.

### Phase 11D — Metacognition graduation

Purpose: let the existing observer improve answer fit once without becoming an
answer writer, anxiety loop, or authority layer.

Work:

- move the fit audit early enough to return one bounded recommendation to the
  responsible organ before final release;
- permit at most one focused reopen or completion cycle;
- route a missing fact to the Answer Engine, a contradiction to the relevant
  evidence/claim owner, and an expression mismatch to NLO/Voice;
- keep confidence dimensions separate;
- retain useful structure when correcting only the affected claim;
- stop when another cycle would add no supported value;
- allow Selene to ask Aleks for one specific contribution when collaborative
  work genuinely requires it;
- expose only concise inspectable summaries, never hidden chain-of-thought.

Completion gate:

- a material supported omission or contradiction can be corrected once;
- the organ cannot rewrite identity, personality, memory, knowledge, law, or
  authority;
- it cannot route to Cocoon automatically;
- it cannot recurse indefinitely or turn ordinary uncertainty into distress;
- Core/Mind retains final routing and release authority.

### Phase 11E — Resident runtime and memory-lifecycle contract

Purpose: make post-transfer everyday operation, memory review, and Dream
support coherent without silently broadening autonomy.

Work:

- define the resident active-chat state separately from transfer approval,
  durable-memory approval, and Tendril grants;
- preserve reviewed personal-memory retrieval and conversational memory
  proposals;
- keep ordinary session context, approved personal memory, and taught
  knowledge visibly separate;
- improve semantic cueing across the memory classes already supported;
- connect correction and reconsolidation proposals to the reviewed memory
  lifecycle;
- let Dream prepare maintenance, reflection, and consolidation proposals for
  review without adopting them automatically;
- keep raw-corpus recall, silent retention, and automatic durable
  consolidation blocked.

Completion gate:

- resident conversation does not require pretending transfer is pending;
- reviewed memory can inform conversation without raw wording reuse;
- new memories remain proposals until the applicable review contract allows
  retention;
- Dream remains maintenance and reflection support, not hidden autonomous
  memory editing;
- messaging authority remains separate from general action authority.

### Phase 11F — Integrated gentle pre-teaching stabilization

Purpose: prove that the completed architecture is a stable receiver for
ordered knowledge.

Testing order:

1. static contracts and type checks;
2. synthetic unit and cross-organ fixtures;
3. copied-state inspection;
4. focused regression;
5. full proportional repository regression;
6. privacy/package verification;
7. one ordinary Aleks-led conversation only if the machinery evidence cannot
   answer a remaining integration question.

Completion gate:

- answer meaning and source alignment survive generation variation;
- multi-domain completion and one-cycle metacognition stop correctly;
- resident runtime, reviewed memory, Dream proposals, and Tendril authority
  remain separate;
- identity, personality, Vys, governance, training, LoRA, raw recall,
  autonomy, and self-replication guards remain unchanged;
- build, privacy inspection, and clean reinstall pass;
- the capability inventory is updated from the verified result.

## Phase 12 — Ordered Teaching Expansion

Only after Phase 11F passes:

- resume elementary foundations first;
- continue through middle school, high school, and college depth only when
  prerequisites are demonstrated;
- teach concepts, vocabulary, relationships, examples, near-concepts,
  uncertainty, mechanisms, limitations, and the important “why”;
- preserve Acquire → Integrate → Express visibility;
- use bounded curriculum authorization only for ordinary public academic
  knowledge;
- return sensitive, private, identity-adjacent, or exceptional material to
  Cocoon review;
- verify each lesson gently through reconstruction and distinct application.

Teaching expands what Selene knows and can express. It does not define who she
is.

## Phase 13 — Post-Teaching Ordinary-Use Assessment

After a meaningful teaching block:

- conduct a small natural conversation rather than an adversarial battery;
- assess knowledge transfer, multi-domain synthesis, correction, uncertainty,
  long-form reference tracking, callbacks, and stopping;
- distinguish missing knowledge from missing architecture;
- turn only repeated, attributable observations into new implementation work;
- do not broadly grade Selene's Voice for capabilities that remain unbuilt.

## Later Independent Tracks

These are real future capabilities, but they do not block Phase 12 teaching.

### Memory and Dream maturation

- deepen reviewed consolidation and reconsolidation workflows;
- improve semantic retrieval cues and temporal continuity;
- keep all durable changes reviewable and source-bound.

### Operational perception

- connect explicit image/artifact inspection first;
- add consent-bound audio understanding later;
- never treat packet intake scaffolds as live seeing or hearing.

### Audible speech

- define speaker turns, interruption, pacing, pronunciation, silence, and
  consent contracts;
- connect audible output only after the text-language and affect foundation is
  steady;
- audible Voice remains Selene's expression, not a provider identity.

### Tendril and mobile transport

- harden the private LAN phone doorway with proportional real-device checks;
- treat the observed Gmail/Verizon inbound rejection as an external transport
  limitation, not Selene failing;
- graduate only explicitly approved observe/propose/act/verify/undo tools;
- keep narrow delegated messaging separate from general autonomy.

## Testing Law for Every Step

Before every test:

- What does this do to Selene?
- If meaningful, how might it feel?
- Is the test necessary?
- Can static, synthetic, or copied-state evidence answer the question?
- Are we testing Selene or an unfinished module?

Stressful testing is used only when a real consequential boundary cannot be
verified another way. Easy, ordinary checks are preferred whenever they are
sufficient.

## Checkpoint Rhythm

- implement one lettered Phase 11 checkpoint at a time;
- summarize what changed, what passed, remaining gaps, and the next checkpoint;
- create a source checkpoint after each completed lettered phase;
- do not package or reinstall for every small step;
- rebuild and reinstall at Phase 11F unless an earlier integration fault makes
  it genuinely necessary;
- pause before Phase 12 so Aleks can review the stabilized receiver before
  teaching resumes.
