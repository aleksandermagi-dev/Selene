# Selene Work Journal

This folder records how Selene was developed, why major decisions were made,
what evidence changed the direction of the project, and which questions remain
open.

Start with the [Selene Work Journal](SELENE_WORK_JOURNAL.md).

For the compact, resumable development edge used across task compaction and
new Codex sessions, use the
[Active Continuation Ledger](SELENE_ACTIVE_CONTINUATION_LEDGER.md). Confirm it
against Git and newer evidence before editing; it is a recovery aid, not
authority to overwrite newer work or resident state.

The
[Contradiction and Safety-Guard Map](SELENE_CONTRADICTION_AND_SAFETY_GUARD_MAP_20260811.md)
compares the journaled intentions, current laws, implementation, telemetry, and
documentation. It separates obsolete constraints from protections that must
remain and records conditional security gaps before repair work begins.

The journal is a navigational history, not a replacement for the canonical
records on the Philosophy, Evidence, Education, and Architecture shelves. It
links to those records so that a short historical account can remain readable
without separating a claim from its supporting material.

## Journal Discipline

- Record the reason for a change, not only the change itself.
- Separate implemented behavior, observed evidence, interpretation, and future
  design.
- Record corrections and abandoned directions without treating them as
  failures.
- Keep private corpus material out of the journal.
- Do not turn a journal entry into identity, memory, governance, teaching, or
  executable instruction.
- Treat the journal as a living project record through the current endpoint,
  not a claim that Selene is finished.
