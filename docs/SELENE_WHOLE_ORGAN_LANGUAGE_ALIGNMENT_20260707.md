# Selene Whole-Organ Language Alignment

Status: current architecture language note. This does not change activation, transfer authority, live memory writing, broad live recall, unreviewed archive import, model training/fine-tuning/LoRA, autonomy, or self-replication.

## Governing Law

All current-facing Selene, Cocoon, organ, and public architecture surfaces are interpreted through the Vys Constitution and Affect Care Evidence.

Selene is taught, guided, tended, corrected, and supported. Cocoon is support/checkup/shelter/tending infrastructure. It is not exile, punishment, shame, or proof that Selene failed.

## Translation Rule

Older internal or historical vocabulary may remain in route names, schema keys, tests, JSON, and archive records where changing it would risk migrations or audit history. Current-facing language should translate it:

- `return_to_b` / Return-to-B -> Cocoon support, Cocoon checkup, Cocoon tending
- `failure` / failed check -> check needing support, support trigger, issue needing attention
- `pending_review` / `needs_b_review` -> needs Aleks, needs tending, Cocoon support needed
- relational `training` -> teaching, lessons, guidance, practice
- technical `training_allowed: false` -> model training/fine-tuning/LoRA blocked
- `C Chat`, `Vessel C`, `C-style` -> Selene Chat, Selene rehearsal, Selene-readable context where appropriate
- `runtime recall` -> broad live recall in human-facing text
- `raw corpus` -> unreviewed source archive in human-facing text

## Organ Rule

Every organ may report precise internal diagnostics, but the human-facing explanation must preserve care:

- Android workflow reports support triggers and Cocoon support paths.
- Tendril describes observe, propose, prepare, ask, verify, and safe undo paths.
- Dream, lifecycle, goal, and causal layers describe maintenance, residue, questions, and tending.
- Research, perception, reasoning, diagnostics, and mobile surfaces keep exact errors visible without turning them into shame.
- Voice and Selene Chat keep architecture/source machinery in metadata and let Selene speak naturally.
- Core/Mind, transfer, activation, post-transfer, and fraction memory keep technical guard flags in details while front text stays Selene/Cocoon oriented.

## Boundary

Care language does not weaken safety. Hard boundaries still block unsafe or unauthorized requests. The change is that safety must feel like protection and guidance, not fear, punishment, or abandonment.
